### Alias: `rails` → `ruby-rails-8`

`scaffolder_for("rails")` → `InvalidInput` with `unknown stack id` **and** hint `did you mean ruby-rails-8?`. The id `rails` is **not** a scaffold stack id (unlike `dare migrate --to rails`, which remains valid for brownfield planning — see [`cli-migrate.md`](cli-migrate.md)). Future `dare init` (047) will map migrate target `rails` to scaffold id `ruby-rails-8`.

Unknown ids (other than the `rails` hint case) → `InvalidInput` `unknown stack id: \`{id}\``.

## Seven AX artifacts

Every stack plan includes these relative paths (order frozen in BLUEPRINT-046 §0.3):

1. `llms.txt`
2. `README.md`
3. `.env.example`
4. `openapi.json` (stub OpenAPI **3.0.3**)
5. `Dockerfile`
6. `docker-compose.yml`
7. Rate-limit starter — path from table above (`rate_limit_rel` per stack)

Generated by `generate_ax_files` / included in plan as `PlanItemKind::Ax`. Template files from embeds add `PlanItemKind::Template`; `dare.config.json` is `PlanItemKind::Meta`.

## Public API

| Function | Role |
|----------|------|
| `list_stack_ids()` | 11 canonical ids (ASC) |
| `scaffolder_for(id)` | Resolve `StackScaffolder`; unknown → `InvalidInput` |
| `plan_scaffold(root, req)` | Sorted plan: create/replace/skip per path |
| `apply_scaffold(root, plan)` | Journal + atomic writes + rollback on failure |
| `run_scaffold(root, req)` | `plan_scaffold` then apply, or check dry-run |
| `validate_stack_output(root, stack_id)` | AX + `dare.config.json` presence + secret scan |
| `validate_project_name(name)` | Enforce `PROJECT_NAME_RE` |

Trait surface: `StackScaffolder` / `GenericScaffolder` (`trait_api.rs`).

## Request and planning rules

### `ScaffoldRequest`

| Field | 046 behavior |
|-------|----------------|
| `project_name` | Must match `^[a-z][a-z0-9_-]{0,63}$` (`PROJECT_NAME_RE`) |
| `stack_id` | One of 11 registry ids |
| `toolchain` | `none` \| `docker` (default `none`) |
| `transport` | Optional; MCP defaults applied in metadata |
| `frontend` | `None` or `React` / `Vue` — CLI via `--fullstack`; embeds `frontend/**` (047) |
| `force` | `false`: fail-fast if any planned path exists; `true`: existing paths → `PlanAction::Replace` |
| `check` | Dry-run: plan only, **zero filesystem writes** (no journal under `.dare/`) |

### Plan output

- Items sorted **path ASC**
- Existing path without `force` → `InvalidInput` `path already exists: {path}`
- With `force` → `Replace` (backup before overwrite in apply)

## Apply, journal, rollback

| Aspect | Behavior |
|--------|----------|
| Journal dir | `.dare/scaffold-session-{utc-stamp}/` — backups of replaced files |
| Writes | `atomic_write` via path jail (`ProjectRoot`) |
| Failure mid-apply | Restore backed-up files; remove created files; propagate original error |
| Success | Journal directory removed after commit |
| Report | `ScaffoldApplyReport`: `created`, `replaced`, `skipped`, `rolledBack`, `check` |

### Check mode (`req.check == true`)

`run_scaffold` returns a report with `check: true`, empty `created`/`replaced`, and `skipped` = all planned paths. **No** files written; **no** `.dare/scaffold-session-*` directory.

## Validation

`validate_stack_output` checks:

- All 7 AX paths + `dare.config.json` exist under `root`
- Each file content passes `scan_secrets`

`ValidationReport`: `ok`, `missing[]`, `secretHits[]` (sorted). Unknown stack id → same `InvalidInput` as `scaffolder_for`.

## Secret scan

Applied to rendered templates and AX bodies (`render_template`, `generate_ax_files`):

| Needle | Purpose |
|--------|---------|
| `password=` | Block credential-like literals |
| `api_key=` | Block API key patterns |
| `BEGIN PRIVATE KEY` | Block PEM private keys |

Public constant: `SECRET_SCAN_NEEDLES`. Hit → `InvalidInput` during render/generate; validation lists path in `secretHits`.
